# Garmin → PostgreSQL → Google Drive (Docker на локальном компьютере или сервере)

[English](README.md) | Русский

Сборщик дважды в сутки (09:00 и 22:00 по Москве) получает настроенные категории данных
из Garmin Connect: суточные показатели, внутридневные измерения и тренировки с подходами
и FIT-файлами. Сохраняет данные в PostgreSQL, выгружает CSV и FIT в Google Drive и делает
резервную копию базы.

## Устройство базы

| Схема | Содержимое | Назначение |
|---|---|---|
| `raw` | Исходные ответы Garmin в JSONB: `raw.daily` — суточные данные, `raw.activity` — тренировки | Источник для пересборки остальных таблиц без повторных запросов к Garmin (`--reparse`) |
| `garmin` | Разобранные таблицы и представления | Анализ и выгрузка |
| `legacy` | Таблицы версии 1 (`daily_metrics`, `sync_state`) | Переносятся автоматически; могут быть удалены после проверки |

**Суточные показатели** — одна строка на день, ключ `day`:

| Таблица | Показатели |
|---|---|
| `garmin.sleep` | Начало и конец сна, фазы, оценка, стресс и пульс во сне, дыхание, SpO2 |
| `garmin.heart` | Пульс покоя за день и средний за 7 дней, минимум/максимум пульса, ночной и недельный HRV, статус и границы нормы |
| `garmin.stress_energy` | Стресс и время по уровням, Body Battery: максимум, минимум, при пробуждении, заряд и расход |
| `garmin.movement` | Шаги и цель, дистанция, этажи, калории, минуты интенсивности, время активности, дыхание днём |
| `garmin.training` | Готовность к тренировке, тренировочный статус, острая и хроническая нагрузка, МПК бега/велоспорта, фитнес-возраст, выносливость |
| `garmin.body` | Вес, ИМТ, жир, мышечная и костная масса, вода |
| `garmin.hydration` | Потребление воды, цель, потери с потом |

**Внутридневные измерения** — ключ по времени: `hr_samples`, `stress_samples`,
`body_battery_samples`, `respiration_samples`, `hrv_samples`, `steps_15min`, `sleep_stages`.

**Тренировки** — ключ `activity_id`:

| Таблица | Содержимое |
|---|---|
| `garmin.activities` | Тип, название, время, длительность, дистанция, пульс, скорость, каденс, мощность, набор высоты, тренировочный эффект и нагрузка |
| `garmin.activity_laps` | Круги и отрезки |
| `garmin.activity_hr_zones` | Время в пульсовых зонах |
| `garmin.strength_sets` | Упражнения, повторы, вес в кг, активные подходы и отдых |
| `garmin.activity_samples` | Измерения тренировки: пульс, скорость, каденс, мощность, высота и координаты |
| `garmin.activity_files` | Реестр скачанных файлов |

`garmin.daily_overview` объединяет суточные показатели и число тренировок по дням.
`garmin.strength_log` соединяет подходы с датами и названиями тренировок.
Дочерние таблицы тренировок ссылаются на `garmin.activities` с `ON DELETE CASCADE`.
Моменты времени хранятся в `timestamptz`, в CSV выводятся по Москве.

## Содержимое папки Google Drive (`RCLONE_REMOTE`)

```text
garmin_daily_metrics.csv        ← garmin.daily_overview
garmin_activities.csv
garmin_strength_sets.csv        ← garmin.strength_log
activities/  garmin_activity_laps.csv, garmin_activity_hr_zones.csv, garmin_activity_samples.csv
intraday/    garmin_hr.csv, garmin_stress.csv, garmin_body_battery.csv, garmin_respiration.csv,
             garmin_hrv_night.csv, garmin_steps_15min.csv, garmin_sleep_stages.csv
fit/         исходные файлы тренировок с часов (ZIP-архивы с FIT)
backups/     резервные копии pg_dump за последние 14 дней
```

## Синхронизация

- Первый проход версии 2 заново обрабатывает историю с самого раннего дня в базе или
  `BACKFILL_FROM`. На каждую дату выполняются 16 суточных запросов; на тренировку — до 6,
  с паузами. Ориентир из исходной документации для 90 дней — 20–40 минут; реальное время
  зависит от объёма и доступности Garmin.
- Последующие проходы перечитывают недавние дни и тренировки с перекрытием `RESYNC_DAYS`:
  Garmin может досинхронизировать данные позже, а пользователь — исправить веса задним числом.
- При HTTP 429 сборщик ждёт 10 минут и повторяет запрос один раз. Повторное ограничение
  останавливает этот этап; следующий проход использует сохранённую контрольную дату.
- Доступность показателей зависит от Garmin и устройства. Пропуски обычно дают пустые поля,
  но в текущей версии ошибки запросов могут затереть ранее сохранённые суточные данные.
  Подробности приведены в разделе ограничений технической документации.

## Команды

```bash
docker compose up -d --build                               # запуск / обновление
docker compose run --rm collector python sync.py --login   # вход в Garmin: email, пароль, MFA
docker compose run --rm collector python sync.py --once    # один проход вручную
docker compose run --rm collector python sync.py --reparse # пересборка из raw.*, без Garmin
tail -f logs/sync.log                                      # просмотр журнала
```

## Доступ к базе с локального компьютера или сервера

Используется `PG_PASSWORD` из `.env`:

```text
psql postgresql://garmin:<PG_PASSWORD>@127.0.0.1:5432/garmin
```

## Настройки

`.env` содержит пароль базы, `tokens/` — токены Garmin, `rclone/` — настройки подключения
Google Drive. Эти пути исключены через `.gitignore`.
